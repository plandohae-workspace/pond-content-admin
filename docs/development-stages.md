# POND Admin 단계별 개발 범위

현재는 **1단계: 검수 관리 메뉴 개선**입니다. 다음 단계의 구현은 사용자의 화면 확인과 명시적 승인 후 시작합니다.

| 단계 | 범위 | 진행 조건 |
|---|---|---|
| 1 | 행 중심 검수표, 오류 CRUD, 스크린샷, 차수·콘텐츠 필터, 이미지 포함 Excel | 현재 검증·화면 확인 대상 |
| 2 | Lesson 관리 및 제작 일정 | 1단계 화면 확인·승인 후 |
| 3 | 자료 관리 및 제출 현황 | 2단계 화면 확인·승인 후 |
| 4 | 대시보드 통합 연동 | 3단계 화면 확인·승인 후 |
| 5 | 사용자 권한 및 전체 기능 테스트 | 4단계 화면 확인·승인 후 |

이번 단계에서는 이미 제공한 Lesson·자료·대시보드·권한 화면을 삭제하거나 재설계하지 않습니다. 이 화면을 확인하는 회귀 검사는 이후 단계의 기능 개발을 의미하지 않습니다.

## 공통 데이터 연결

`src/model.js`는 Level → Textbook → Unit → Lesson 관계, ID 기반 조회(`hierarchy`), 검수 연결(`linkedLog`), 호환 마이그레이션(`migrate`)을 공통 제공하며 `src/Hierarchy.jsx`의 `Cascade`는 상위 선택에 따른 하위 목록을 연결합니다.

- `projects`: 기존 프로젝트 ID와 원본 필드를 유지한 Level 목록. 호환성을 위해 저장 키는 유지합니다.
- `textbooks[].levelId` → Level ID
- `units[].textbookId` → Textbook ID
- `lessons[].unitId` → Unit ID. 이전 `projectId`는 호환 필드로 보존합니다.
- `logs[].lessonId`, `materials[].lessonId` → 동일한 Lesson ID
- Class/Activity는 검수 오류 행의 자유 입력값으로만 저장하며 계층 엔터티를 생성하지 않습니다.
- `lessons[].status`(제작/검수 완료), `lessons[].noErrors`(차수별 오류 없음 확인), `logs[].STATUS`(개별 오류 처리 상태)는 별도입니다.

검수 저장은 `applyReviewLogs`를 통해 오류 목록을 교체하고 해당 Lesson·차수의 기존 오류 없음 확인만 필요한 경우 해제합니다. Level·Textbook·Unit·제작 일정·자료 파일 및 알 수 없는 확장 필드는 변경하지 않습니다. 새 오류 저장이 제작 완료를 자동 해제하지 않습니다.

차후 제작 일정·제출 현황은 기존 Lesson ID에 연결해 확장할 수 있습니다. 검수표 표시·Excel 모듈은 데이터를 props/함수 인자로 받아 저장소와 화면 메뉴를 직접 관리하지 않습니다. 외부 서버 없이 IndexedDB를 사용하며 다중 탭 동시 편집 충돌과 서버 인증은 현재 제공하지 않습니다.

## 검증·배포 결과

검수 행 편집, 다중 이미지·원본 확대·교체·삭제·붙여넣기, Lesson·차수 필터, 기존 STATUS 보존, 이미지 포함 Excel, v1 데이터 이전과 다른 메뉴의 유지 여부를 검사합니다. `npm run build:html`로 단일 HTML을 갱신합니다.

GitHub에는 기본 브랜치를 직접 덮어쓰지 않고 1단계 작업 브랜치에 커밋·푸시합니다. 푸시가 거부되면 로컬 커밋 및 거부 이유를 보고하고 원격 저장 완료로 안내하지 않습니다.
