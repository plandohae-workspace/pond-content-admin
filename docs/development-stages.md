# POND Admin 단계별 개발 범위

1~3차 개발은 main에 병합되었습니다. 현재 작업은 사용자가 요청한 **4차: Lesson 관리 프로젝트 보드형 UI 개편**입니다. 기존 단계별 저장·검수·자료 관리 B안을 유지하며, PR 병합은 화면 확인과 명시적 승인 후 진행합니다.

| 단계 | 범위 | 진행 조건 |
|---|---|---|
| 1 | 행 중심 검수표, 오류 CRUD, 스크린샷, 차수·콘텐츠 필터, 이미지 포함 Excel | main 병합 완료 · 회귀 검사 대상 |
| 2 | Lesson 관리 및 제작 일정 | main 병합 완료 · 저장 회귀 검사 대상 |
| 3 | 자료 관리 B안·브라우저 첨부 파일 | main 병합 완료 · 회귀 검사 대상 |
| 4 | Lesson 제작 칸반 보드 UI | 이번 구현·화면 확인 대상 |
| 5 | 사용자 권한 및 전체 기능 테스트 | 4단계 화면 확인·승인 후 |

이번 단계에서는 Lesson 메인 화면을 보드로 개선하고, 기존 검수·자료·대시보드·권한 메뉴는 유지합니다. 이 화면을 확인하는 회귀 검사는 이후 단계의 기능 개발을 의미하지 않습니다.

## 공통 데이터 연결

`src/model.js`는 Level → Textbook → Unit → Lesson 관계, ID 기반 조회(`hierarchy`), 검수 연결(`linkedLog`), 호환 마이그레이션(`migrate`)을 공통 제공하며 `src/Hierarchy.jsx`의 `Cascade`는 상위 선택에 따른 하위 목록을 연결합니다.

- `projects`: 기존 프로젝트 ID와 원본 필드를 유지한 Level 목록. 호환성을 위해 저장 키는 유지합니다.
- `textbooks[].levelId` → Level ID
- `units[].textbookId` → Textbook ID
- `lessons[].unitId` → Unit ID. 이전 `projectId`는 호환 필드로 보존합니다.
- `logs[].lessonId`, `materials[].lessonId` → 동일한 Lesson ID
- Class/Activity는 검수 오류 행의 자유 입력값으로만 저장하며 계층 엔터티를 생성하지 않습니다.
- `lessons[].status`(제작/검수 완료), `lessons[].noErrors`(차수별 오류 없음 확인), `logs[].STATUS`(개별 오류 처리 상태)는 별도입니다.

검수 저장은 `applyReviewLogs`를 통해 오류 목록을 교체하고 해당 Lesson·차수의 기존 오류 없음 확인만 필요한 경우 해제합니다. Level·Textbook·Unit·제작 일정·자료 파일 및 알 수 없는 확장 필드는 변경하지 않습니다. 이 저수준 함수는 기존 제작 데이터를 변경하지 않습니다. 2단계 공통 저장 함수는 `reconcileLessonReviews`를 추가 적용하여 새 단계 관리가 있는 Lesson의 미해결 검수 단계만 재개합니다. 원래 완료일과 변경 이력을 남기고, 저작 완료 등 다른 제작 단계는 유지합니다.

차후 제작 일정·제출 현황은 기존 Lesson ID에 연결해 확장할 수 있습니다. 검수표 표시·Excel 모듈은 데이터를 props/함수 인자로 받아 저장소와 화면 메뉴를 직접 관리하지 않습니다. 외부 서버 없이 IndexedDB를 사용하며 다중 탭 동시 편집 충돌과 서버 인증은 현재 제공하지 않습니다.

## 검증·배포 결과

검수 행 편집, 다중 이미지·원본 확대·교체·삭제·붙여넣기, Lesson·차수 필터, 기존 STATUS 보존, 이미지 포함 Excel, v1 데이터 이전과 다른 메뉴의 유지 여부를 검사합니다. `npm run build:html`로 단일 HTML을 갱신합니다.

GitHub에는 기본 브랜치를 직접 덮어쓰지 않고 이번 단계 작업 브랜치 `codex/pond-lesson-stage4`에 커밋·푸시합니다. 푸시가 거부되면 로컬 커밋 및 거부 이유를 보고하고 원격 저장 완료로 안내하지 않습니다.

### 1단계 추가 개선: 레벨별 검수 탐색

검수 메뉴의 첫 화면을 6개 초기 레벨 카드로 변경하고 선택한 Level의 관리 데이터에서 교재·Unit·Lesson을 조회합니다. 기존 다른 메뉴 화면은 유지합니다. 검수 차수는 상단 탭으로 전환하며, 전 레벨 통합 조회와 소속 확인 필요 조회는 별도로 제공합니다. 초기 데이터 추가는 이름이 정확히 일치하는 Level만 재사용하고 기존 ID의 소속을 추측해 변경하지 않습니다. 이번 작업은 2단계 제작 일정 개발의 시작이나 승인으로 간주하지 않습니다.
